# 掌握度评价标准

评价实际展示出的能力，而不是用户的信心、学习时长或复制得到的代码。

## 证据维度

| 维度 | 所需证据 |
|---|---|
| 解释 | 能用自己的语言说明目的和机制 |
| 追踪 | 能完整追踪消息、TF、状态、回调或进程生命周期 |
| 实现 | 能编写或修改可运行的代码和配置，并正确声明依赖 |
| 验证 | 能通过命令、日志、可视化或测试检查行为 |
| 排错 | 能把可观察现象与可能原因联系起来，并验证修正结果 |
| 迁移 | 能把知识应用到移动机器人或新的使用场景 |

没有得到证据的维度应标记为**尚未观察**，不能直接判定为失败。

## 掌握等级

### 未掌握

无法解释核心机制，或者仍依赖实质错误的理解。仅有从课程复制并能够运行的代码，不能提高该等级。

### 初步掌握

能够解释基础概念和识别主要组件，但还不能可靠追踪运行过程、独立复现结果或分析典型故障。

### 可以应用

能够独立解释、实现和验证相关概念，并能分析至少一个典型故障。运行记录或仓库证据能够支持该判断。

### 项目级掌握

已经达到“可以应用”，并且能够把相关概念迁移到自己的移动机器人项目，说明设计选择，并在没有逐步提示的情况下处理真实面试追问或新的故障。

## 评级规则

- 使用核心维度中得到证据支持的最低等级，而不是取平均值。
- 不能用较强的定义记忆掩盖缺少运行证据的问题。
- 如果缺少运行证据，可以给出暂定等级，但必须说明什么观察结果能够确认该等级。
- 如果因果模型正确，不应因语言表达、翻译或少量API名称记忆不准确而降低等级。
- 如果发布者与订阅者角色颠倒、回调与执行器机制错误、TF方向或时间理解错误，或者混淆模型几何和状态，应降低等级。
- 只有出现新的实际证据时才能提高等级。
- 课程项目能够运行，并不自动代表达到项目级掌握。

## 第六章验收参考：URDF、Xacro与Gazebo

这是相似机器人建模章节的参考，不要求每次机械地执行全部项目。

达到**可以应用**，应有证据证明用户能够：

1. 解释 `link`、`joint`、`joint origin` 和 `visual origin`；
2. 追踪 `/joint_states`、`robot_state_publisher` 和固定/动态TF；
3. 预测缺少 `/joint_states` 时的行为；
4. 区分移动视觉模型与移动坐标系；
5. 展开Xacro并验证生成的URDF；
6. 检查Gazebo传感器话题或消息坐标系；
7. 追踪 `/cmd_vel` 经过控制器到轮子命令接口的过程；
8. 验证至少一个典型运行或配置修正。

达到**项目级掌握**，还应具备：

- 将知识独立迁移到自己的移动机器人模型；
- 能说明TF、传感器、控制器和里程计的设计选择；
- 无需预先给定排错步骤即可分析新故障；
- 有与SLAM、定位或导航等下游系统集成的证据。
